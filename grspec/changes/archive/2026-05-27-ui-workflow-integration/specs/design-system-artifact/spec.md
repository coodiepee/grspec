## ADDED Requirements

### Requirement: Design-system directory convention
The system SHALL recognize `design-system/` as an optional subdirectory within a change directory, containing design-system output generated by `grspec ui design-system --persist`.

The directory SHALL follow this structure:
- `MASTER.md` — global design-system rules (REQUIRED if directory exists)
- `<page-name>.md` — optional page-specific override files

#### Scenario: Valid design-system directory
- **WHEN** a change directory contains `design-system/MASTER.md`
- **THEN** the system SHALL recognize it as a valid design-system artifact

#### Scenario: Page overrides alongside MASTER.md
- **WHEN** a change directory contains `design-system/MASTER.md`, `design-system/landing.md`, and `design-system/dashboard.md`
- **THEN** all three files SHALL be discoverable as design-system context

### Requirement: Design-system is not a schema artifact
The `design-system/` directory SHALL NOT be registered as an artifact in `schema.yaml`. It SHALL have no entry in the artifact dependency graph, no completion detection, and no gate-blocking behavior.

#### Scenario: Schema artifacts unchanged
- **WHEN** the `spec-driven` schema is loaded
- **THEN** the artifact list SHALL contain exactly `proposal`, `specs`, `design`, `plan`
- **AND** no `design-system` artifact SHALL exist

#### Scenario: Missing design-system does not block apply
- **WHEN** `generateApplyInstructions` is called for a change without `design-system/`
- **AND** all required schema artifacts (proposal, specs, design, plan) are complete
- **THEN** the apply state SHALL be `ready`

### Requirement: ui-detected metadata field
The `.grspec.yaml` change metadata file SHALL support an optional `ui-detected: boolean` field. When present and `true`, downstream workflow skills MAY include UI-specific guidance without re-scanning the proposal.

#### Scenario: Metadata with ui-detected
- **WHEN** `.grspec.yaml` contains `ui-detected: true`
- **THEN** the metadata reader SHALL parse and return `uiDetected: true`

#### Scenario: Metadata without ui-detected
- **WHEN** `.grspec.yaml` does not contain a `ui-detected` field
- **THEN** the metadata reader SHALL return `uiDetected` as `undefined` or `false`

#### Scenario: ui-detected does not affect artifact completion
- **WHEN** `detectCompleted` evaluates change artifacts
- **THEN** the `ui-detected` field SHALL have no effect on completion status
